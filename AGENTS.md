# AGENTS.md — handover notes

For whoever maintains this next, human or AI. Read this before changing `ClaudeTray.ps1`.

## What it is

One file, `ClaudeTray.ps1`, Windows PowerShell 5.1 + WinForms/GDI+ (.NET Framework 4.x). No build step,
no dependencies, no admin rights. Target: Windows 10 1809+ and Windows 11.

## How it works

```
-Login ──► browser: claude.ai/oauth/authorize (PKCE S256, separate random state)
            user pastes CODE#STATE ──► POST /v1/oauth/token (platform.claude.com, then console.anthropic.com)
            ──► oauth.json  {format:"dpapi", data:<DPAPI(CurrentUser) of {claudeAiOauth:{...}}>}

-Run (hidden, detached worker) ──► every pollSeconds:
            GET api.anthropic.com/api/oauth/usage   (Authorization: Bearer, anthropic-beta: oauth-2025-04-20)
            ──► ConvertTo-Limits: every top-level object with a `utilization` field
                (five_hour, seven_day, seven_day_opus, ... ; nulls and disabled extra_usage skipped)
            ──► tray icon = max(utilization)   (ring + number)
            ──► hover flyout = all limits       (New-PanelBitmap, drawn to a bitmap, shown in a no-activate window)
```

- Token near expiry or HTTP 401 ⇒ `Update-Token` (refresh grant), written back encrypted. A Claude Code
  credentials file (`%USERPROFILE%\.claude\.credentials.json`) is used read-only as a fallback and is
  **never** refreshed (that would rotate Claude Code's refresh token and sign it out).
- Any start request (no switch, `-Restart`, `-Login`, `-Install`) launches a hidden `-Run` process and
  returns, so closing the console never kills the tray. Shortcuts (Start menu + Startup) run `-Run`.
- Single instance: mutex `Local\ClaudeTray`; `Stop-Others` kills other `-Run` workers first.

## Testing a change

There's no Windows in a typical AI sandbox, and GDI+ won't render on Linux. Work like this:

1. Static check (any OS with PowerShell 7): `pwsh -File tools/check.ps1` - parse errors + locals that shadow
   script globals (the #1 source of bugs here: a handler's `$k = ...` broke every `px()` call).
2. Unit-test pure functions by extracting them from the AST (e.g. `ConvertTo-Limits`, `Log`, `Format-Reset`)
   and feeding mock data.
3. On Windows: `-Once` renders `logs\preview_icons.png` (all sizes × light/dark), `logs\preview_popup.png`
   (real data) and `logs\preview_popup_mock.png`, and logs one fetch — look at these, don't guess.
4. Then start it for real (no switch) and read `logs\claudetray.log`.
5. `-Screens` regenerates the README images in `docs\`.

## Windows PowerShell 5.1 pitfalls (all hit for real)

- **Variable names are case-insensitive and scoping is dynamic.** A local `$s` in a function overwrites
  the global `$S` (usage state) for every function it calls. This made the icon read "no data" and the
  tray crash. Never name locals after globals: `$S $UI $Cfg $k $tray $pop $Accent $NumFont $LightTaskbar`.
- **`$x = if (...) { ... $_ ... }` inside a pipeline loses `$_` in 5.1** (works in PS 7). Use a
  `foreach ($item in ...)` statement instead.
- `HttpWebRequest`: restricted headers (`User-Agent`, `Referer`, `Content-Type`, `Accept`) must be set via
  properties, not `.Headers[...]` (see `Invoke-Http`).
- Don't `Bitmap.SetPixel` while a `Graphics` for that bitmap is alive (lock error).
- `NotifyIcon.Text` is capped at 63 characters.
- Source file must stay **UTF-8 with BOM**; without it 5.1 reads it as ANSI and mangles non-ASCII.
- Exceptions can contain values (one leaked a session key into the log once) — `Log` masks
  `sk-ant-...` and `Bearer ...`; keep it that way.

## Things already tried — don't redo

- **claude.ai cookies / sessionKey**: claude.ai sits behind a Cloudflare JS challenge that blocks
  non-browser HTTP clients (403 "Just a moment…"). Reading the Claude desktop app's cookie store also
  fails while the app runs (exclusive lock). The OAuth path above avoids both.
- **Forcing the icon out of the overflow area**: Windows doesn't allow it for a script-hosted icon;
  it's a one-time user toggle.
- **Using the Claude logo** as the icon: it's Anthropic's trademark — don't ship it.

- Bump `$Version`, add a `CHANGELOG.md` entry, run `-Once` and `-Screens`, check the images.
- `git status --ignored` must show `oauth.json`, `config.json`, `logs/` as ignored — never commit them.
- Grep the diff for `sk-ant-`, `Bearer`, e-mail addresses and personal paths before pushing.

## Quest log

- Tray-mode section (from `# ---- tray mode`) holds everything: quest reading (`Read-Quests`, derived state
  act/done/working, `Visible` via `state.json` hidden map), results (`Get-Results` resets when
  `quest_updated` differs), `Start-Step`/`Poll-Running` (2 s `$questTimer`; hidden cmd/ps with redirected
  output in `%TEMP%\claudetray_*`, admin via `-Verb RunAs`, interactive = visible console), `Send-ToChat`
  (deep link + UIA), and the WinForms flyout (`Build-Rows` rebuilds all
  controls; handlers use `$this.Tag` and call `Request-Build` so the rebuild happens on the UI timer, never
  inside a handler of a control being disposed).
- Variable-name traps added: `$QS` (quest store) vs `$q`, `$Gly` (glyphs) vs `$g` (Graphics), `$T` palette
  vs `$t`, `$k` DPI scale used by `px` - never shadow these in functions.
- Icons are drawn with GDI+ in `Get-IconBmp` (cached, `SetResolution` to the screen DPI or WinForms rescales
  and clips them); `-Screens` writes `docs/iconset.png` to review them.
- App watcher: `$probeScript` runs in its own runspace, fills the synchronized `$Probe` (Page = web document name
  `<chat title> - Claude`, Working = a button matching `$stopRx` exists). The app's window title is only
  "Claude" - never match on it alone. Chat titles can contain `[ ]`: never use `-like` with them.
- `Send-ToChat`: deep link only if the chat isn't the open page, paste via UIA + clipboard, queue when
  `Test-ChatWorking`, then restore the previous foreground window / minimized state.
- Log lines worth grepping: `send:`, `app:`, `queue:`, `build`, `show (`/`hide (`, `UI exception`.

## Lessons from live testing (keep)

- PRIVACY: never log the whole UI tree. The sidebar exposes the user's chat titles (one held a home address).
  Diagnostics log composer controls only.
- WM_SETREDRAW(TRUE) shows a hidden window: only freeze redraw while the flyout is visible.
- Never trust a writer's clock: quest `updated` was written as fake future times and broke status + preview.
  The tray uses the file's write time.

- Never paste into a non-empty composer: the user's draft and the tray text merge into one message
  (happened). `Send-ToChat` reads the box first and aborts.
- Verification looks at the last "Vous avez dit : ..." / "You said: ..." button the app exposes.
- Every UI control used to get its own ToolTip (= a native window, never freed). Use the shared `$TT`.
- The app queues a message sent while Claude works ("Envoyer maintenant" / Ctrl+Enter = send now), so the
  tray just pastes + Enter (`holdWhileWorking` false by default); verification counts "queued in the app".
- Iteration loop that works: tools/check.ps1 -> deploy -> verify size on the device (the first write often
  doesn't land) -> commit -> write the quest -> the user runs it from the tray -> read results + log.

## Web engine (`engine: auto`)

- `$webScript` runs in its own runspace. It keeps a headless Edge (`--headless=new`, normal user agent, own
  profile in `browser-profile\`, `--remote-debugging-address=127.0.0.1`) with one tab per visible quest chat,
  and talks to it over CDP with .NET `ClientWebSocket` (`Cdp` helper).
- Tabs are tracked by target id (`$tabOf`): claude.ai rewrites URLs after load. Extra claude tabs are closed;
  a free one is reused (Page.navigate) before opening a new one.
- State JS (`$js`): composer = `div.ProseMirror[contenteditable=true]`; working = a stop/arrêter button or
  `[data-is-streaming=true]`; messages = `[data-testid=user-message]` / `[data-testid=assistant-message]`
  (Claude Code sessions; claude.ai chats also matched by `.font-claude-response`). Reply = assistant blocks after
  the last user message.
- Send = focus composer, `Input.insertText`, Enter key events (same as a person: the app's queue applies while
  Claude works). Stop = click the stop button. Results go back through `$Web.Results`; delivery is confirmed by
  the user-message count or `working`.
- The desktop-app watcher (UIA) remains the fallback when the browser isn't ready (`sendVia: app` forces it).
- Our own Edge is recognised by its command line (`--headless` + our port); a visible browser on that port
  is closed and relaunched headless.

## Panel UI (`ui: web`)

- `ui\panel.html` (one file: HTML + CSS + JS, CSP: no network) hosted in a WebView2 control docked in `$pop`.
  `Init-WebUi` (just before `Application.Run`) -> `On-WebInit` -> `NavigateToString` -> page posts `ready` ->
  `$UI.WebReady`, classic `$content` hidden. Any failure -> `Disable-WebUi` (classic panel).
- PS -> page: `Push-WebState` posts ONE JSON state (`type: state`) and only when it changed (UI timer every
  250 ms while shown, 1 s hidden). Messages of the open chat are serialised separately per chat and cached by a
  size signature (`__MSGS_n__` placeholders) so the per-tick cost stays small.
- Page -> PS: `{type: ...}` messages handled in `On-WebMsg` with the same functions as the classic panel
  (`Send-ToChat`, `Stop-Chat`, `Start-Step`, `Toggle-Manual`, `Set-StepResult`, `Open-Chat`...).
- Card views: `opened` (compact or full) and `big` (full) sets in the page; title click = collapsed <-> open (full; the compact view and its `.vw` cycle button were removed),
  Collapsed shows the one-line `.mi` input (Enter = `doSend(id, true)`); open shows the conversation + composer.
  `.conv` = `.msgs` (patched message list) + `.actw` (this round's steps, only while `st == act`) + `.askw` (page
  prompts): one scroll. No activity text (`act` is still read but not shown).
  The page posts `expand` {ids, big}; PS keeps `$UI.WebOpen` / `$UI.WebBig` and sends them back as `expanded` / `big`,
  applied only on the page's first state (after a reload). Title click on a compact card goes full.
- `skill` per chat (`Test-TraySkill`): Claude wrote a quest (not a `tracked` placeholder), a bridge quest, or a message
  started with `/tray`. The page's `.trc` chip (armed unless clicked, `trayArm`) sends `tray: true` -> PS prepends `/tray `.
  Claude finishing without a new quest -> `done` once the tab went idle after your last send (`EndAt` > `LastSent`).
- Slash list: `slash` -> web command types "/" into the chat's empty composer, reads `[role=option|menuitem]`, Escape,
  clears; cached in `$UI.Slash` 10 min, sent as `slash` {items:[{n, d}]}. The page's `#slp` popup completes the box.
- Tray click: `$UI.ClickWas` (open/closed before the click) -> hide (forced even when docked) / show + pin; the double-click
  handler undoes it, then `Open-ClaudeApp`. Settings are an HTML menu (`setMenu`, posts `menuact` {k, v}); the WinForms
  `$menu` stays for the tray icon's right-click. `debugLog` gates every `DEBUG` line (`Log`), adds `Write-DebugSnapshot`
  each minute and page `ui:` lines. Resize: `.rz` edge divs post `rsz` {e} -> `$rszTimer` -> `panelWidth`/`panelHeight`
  (CSS px) + `Set-DockHere`; `Fit-WebPop` uses `panelHeight` when set; `$pop.add_Resize` undoes a maximize.
- Wheel: the page routes a wheel nothing under the pointer can take to the open conversation, else `#list` / `#pins`.
- Layout (`LAY`, page-owned, saved by PS in state.json `layout` via the debounced `layout` message): `sec` [{id, name,
  sort, col}] (`main` always exists), `at` {chatId: secId}, `ord` (manual order, new chats on top), `browse`, `open`/`big`.
  `viewOf` re-sorts a section only while the panel is hidden or after a user change (`dirtyView`). Pinned chats (`c.pin`,
  PS `$QS.Pins`) render in `#pins`. Drag = HTML5 DnD on `.head` (`dragId`); card file-drop handlers ignore it.
  Per chat PS sends `ts` (quest file time, ms), `kind`, `proj` (from the catalog, cached in state.json `proj`).
- Browse: catalog (`$catJs`) lists 300 recent chats with project ids; `catproj` (`$catProjJs`) lists one project's chats
  (tries `/projects/<id>/conversations`, then `chat_conversations?project_uuid=`). The catalog is reused for 3 min.
- Start modes (`startWith`): the Startup shortcut runs `-Run` (windows) or `-Run -WaitClaude` (claude), none for manual;
  `-WaitClaude` waits after the mutex for a `claude` process with a main window (the CLI has none).
- Page order: `order` follows the tray's list only while `S.shown` is false; while shown, new chats go on top and nothing
  moves. Cards missing from a state stay 5 s (quest file mid-write) unless you hid them (`hideNow`). `patchList` diffs the
  conversation by common prefix / suffix. `setActs` keeps the focused answer box; typed answers live in `cd.obs`.
- Failed sends: PS sets `$UI.Drafts` -> page `draft`/`draftV` -> back into `cd.sentFrom` box (+ `cd.sentFiles`).
- `tools/check.ps1` also runs `node --check` on the panel pages and the injected scripts when node is installed.
- Pins: `pinc` toggles `$QS.Pins` (ordered, state.json `pins`); a pinned chat is always `Visible` (hide unpins it) and the
  page puts it in `#pins`, a fixed section above the scrolling `#list` (max 60 % of `maxH`, own scroll). Hidden chats come
  as `hidden` [{id, title, age}]: a muted "N hidden" line at the end of the list lists them, `unhide` brings one back.
  `track` of a chat the tray already knows only unhides it (never overwrites its quest with a placeholder).
- Layout = accordion: every chat is a card in one scroll; a click on its title expands it in place (its own
  conversation scroll, steps, composer). The page owns the expanded set and posts `expand` (ids); PS keeps it in
  `$UI.WebOpen`, which drives `$Web.MsgFor` (the hidden tabs only read messages for expanded chats) and is
  sent back as `expanded` after a page reload. Chats expand by themselves when they get new steps.
- Claude's long messages (> 240 chars or code/table) show as a 1-2 line text preview + "more" (no fade: unreadable).
  Hover one 450 ms -> page posts `col` {x: L|R, open, key, title, html} -> `Show-SideWin`: a separate small
  window (`ui\side.html`, own WebView2, same runtime process) next to the panel. The panel never resizes (a
  resizing WebView2 jumps for a frame). Side events (`hover`, `pin`, `close`) come back to PS and go to the
  page as `colev`. Two columns: a pinned one stays, hovers use the other side when `roomL`/`roomR` allow.
  Columns stay open while the cursor is in a conversation or a column; they follow the panel; Hide-Pop hides them.
- Zoom: Ctrl+wheel posts `zoom` -> `Set-WebZoom` (ZoomFactor on every WebView2, `panelZoom`, default 0.9);
  widths/heights convert CSS px with `$k * $UI.Zoom`.
- Files, you -> Claude: paste / drop / 📎 in a composer -> page reads them (FileReader, <= 15 MB, 5 max) and posts
  `send` with `files` [{name, type, b64}] (big JSON -> `ConvertFrom-BigJson`, PS 5.1 ConvertFrom-Json chokes) ->
  `Save-Upload` (%TEMP%\claudetray_up) -> web `send` command: `DOM.setFileInputFiles` on the page's first
  `input[type=file]`, waits for the composer to stop being busy (max 25 s, logged), then text + Enter.
- Files, Claude -> you: `$fileJs` finds file cards / links in a message (`f` = names, `x` = absolute message
  index). Chip Save/Copy posts `dl` -> web `dl` command: fetch the link with the page's session (base64 read
  back in 400 KB chunks) or click its download button (`Page.setDownloadBehavior` into a temp folder) ->
  `Poll-Downloads` -> `Finish-Download` (Downloads, no overwrite; Copy = file drop list on the clipboard).
  Failures and newly expanded chats queue a `diag` command: STRUCTURE ONLY (tags, test-ids, href kinds) in the
  log - use it to fix the selectors when claude.ai changes.
- New chat (`+`): page posts `catalog` (projects via claude.ai `/api/organizations[/<org>/projects]`, page session)
  and `newchat` {project, name, model, think, text}. Web commands with `Id = '__new__'` run outside the per-chat
  loop: open claude.ai/new (or /project/<id>) in a new tab, `$pickJs` (model menu + thinking toggle, best effort,
  logged), insert text, Escape (closes the /tray slash popup), Enter, wait for /chat/<uuid>, rename via PUT
  chat_conversations. `Poll-NewChat` then writes a placeholder quest (+ results `sent`) so the chat shows at once;
  Claude's own quest replaces it. The name is applied again after 30 s (auto-title). `/tray` is prepended.
- Chat parity: the state JS (`$js`) also returns `act` (Claude's current step row: role=button / aria-expanded /
  summary in the last reply), `prompts` (visible buttons the page wants pressed - Allow / Deny / Continue... - in
  dialogs and around the last reply; kept in `window.__ctPrompts`, pressed by index + label check via `press`),
  `model` (model selector text) and `retry` (claude.ai's retry button). `$msgJs` drops step rows from replies and
  keeps https links as `<a data-href>` (page: click -> `openurl`, PS opens only http/https). Code blocks get a copy
  button in the page. A balloon tells you when a page starts asking.
- Bridge mode (docs/PROTOCOL.md): `$js` returns a `tray-quest` JSON block from Claude's current reply -> `Poll-Bridge`
  writes the quest file; `Get-BridgeLine` appends a `[tray]` results line to the next panel send (once per quest
  version). `$msgJs` hides the block. Steps are locked (`Test-StepsLocked`) while Claude works or after you sent.
- Read marks: the page hashes Claude's last reply (djb2 of the first 300 chars) once its chat is open, the panel is
  shown and the end has been in view 1.5 s -> `read` -> `$QS.Read[id] = {K, At}` (state.json). Replies up to the
  read one are grayed; `Test-Unread` (Claude finished / quest rewritten after `At`) drives bold titles, the purple
  dot and the tray icon. `track` (+ form, recent chats from the catalog) writes a placeholder quest for any chat.
- Tray icon: `Get-IconFlags` (Needs / Working / Unread) -> `New-TrayIcon -flags`; see docs/DESIGN.md "Tray icon".
  The anim timer only runs while working (the user asked: no pulsing). `-Once` writes logs\preview_states.png.
- Under your last message (matched with the results file's last `sent`): what you ticked / answered that round.
- Done/skipped steps collapse to one line (observe answers shown after the label; click to edit).
- Claude's reply HTML comes from `$msgJs` in the web engine (tag whitelist, no attributes) and is cleaned
  again in the page (`clean()`, inert DOMParser). Never relax either side.
- Height: the page reports `size` (CSS px); `Fit-WebPop` converts with `$k`, capped at 70 % of the screen.
- `terse` (menu: Short replies from Claude) adds `"style": "terse"` to every results file; the skill tells
  Claude to answer telegraphically when it sees it (results are read on "check" anyway: zero extra tokens).
- Drag: CSS `app-region: drag` when the runtime supports it (native move loop -> `ResizeEnd` -> `Set-DockHere`),
  else the page posts `drag` and `$dragTimer` follows the cursor.
- Test the page without Windows: Playwright + a mocked `window.chrome.webview` (post a `state` object).
- 0.2.0 bars: `#top` is only the grip; `#gripz` is no-drag, so mousedown posts `drag` (PS `$dragTimer`) and a mouseup
  without moving calls `foldAll`. The tools live in `#tb` above `#usage`; `popMenu(x, y, items, up)` opens menus upward.
- Compact mode (`compact` in config, `body.compact`): a collapsed card hides `.head` and shows `.mini` as one row:
  `.mdot` (data-a `toggle`, draggable) · `.mfld` (the input, placeholder = title · preview) · `.mt` (bell, open, age).
- Hover labels: the page moves `title` to `data-tt` on hover and draws `#tip` (Windows tooltips never show in a
  no-activate window).
- Questions: `$js` returns `q` {t, multi, sub, o:[{l, d, s}]} found by structure (role radio / checkbox / option or
  inputs near the composer or the last reply, largest group of 2-12, nav / aside excluded), with `window.__ctQ` holding
  the elements. The `qpick` / `qsub` commands click them (label checked first). A new question queues a `diag` that
  also logs `ZONE` (the composer's surroundings: tags, roles, types, aria-checked - no text).
- Files: `dl` mode `open` -> `Open-Downloaded` (default app; risky extensions are shown in their folder, never run).
- claude.ai's question card (captured 2026-10, French UI): `[data-testid=hub-ask-user-question-card]` in the composer
  dock (same fieldset as `[data-testid=chat-input]`), `[data-cds=AskUserQuestion]` role=group with `aria-labelledby`
  (question), a nav span "N sur M" between prev / next buttons, options = `button[aria-pressed]` (`bdi` label +
  description), a `form input[type=text]` "Other" with a skip button. One question per step. Answering: Enter in the
  message box sends the picks; text typed in the message box becomes the "Other" answer. `[data-testid=hub-question-announcer]`
  (role=alert) also holds the question. Labels are localized: match structure, not text.
