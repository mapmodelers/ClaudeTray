# Field notes, 2026-10-21 (Claude Enterprise PC, Claude Desktop with Cowork)

For the author. No chat titles, IDs, org IDs or content recorded.

## Summary (read this first)
- Context: everything here was done and field-tested on a **Claude Enterprise** account (single org), Windows 11, Windows PowerShell 5.1, Claude Desktop MSIX 3.1623 with Cowork (local agent) sessions, French UI, by a user of the tray working with Claude in a Cowork session. Notes, diff and code carry no names, emails, chat titles or IDs.
- Package: ClaudeTray.ps1, ui/panel.html, skill/tray/SKILL.md (+ skill/tray.zip) changed; ENTERPRISE-CHANGES.diff = full diff against the unpatched originals; this file = rationale, field results and open issues per patch. Every code change carries an `ENTERPRISE-PATCH-<n>` marker.
- Enterprise finding: no Enterprise-specific failure in the claude.ai web API (sign-in, catalog, org, usage via the web session all fine). The gaps came from **Claude Desktop local (Cowork) sessions**, which claude.ai does not expose, and from Desktop's UI/storage being undocumented. One environmental issue: claude.ai's Cloudflare check can block the tray's hidden browser (usage HTTP 403) until claude.ai is opened once in the tray browser (PATCH-30).

### What changed (by area)
- Desktop local / Cowork chats as first-class chats (PATCH-2..4, 6, 8..14, 18, 20, 28, 36..38): listed and searchable in BROWSE; trackable (id `local/<sessionId>`); state, messages and pending questions read from the session transcript (works with Desktop minimized); questions and request cards answered from the tray; send / stop / answer work even when Desktop shows another chat (the tray switches Desktop to it in the background and back); files/folders given by path; /tray chip writes the command in the field; a /tray message carries `[tray-id] <id> root=<quest folder>` so the session can write its quest.
- Tray UX (PATCH-5, 7, 13, 15, 16, 17, 19, 22, 31, 32): bottom edge fixed on resize; grip restores the exact previous view; immediate feedback after answering; request buttons need a 2nd click; idle chats leave the tray after a cooldown (setting); status icons redesigned, titles never bold; larger resize edges; icon click toggles a pinned panel; settings sub-menu; numbered quest steps; model + effort chip in the reply bar; send button first.
- Robustness / regressions fixed (PATCH-14, 23..26, 29..30, 34, 35, 37): stabilization after a code review (exact title match, no double send, per-chat state...), usage lost when only local chats were shown (PATCH-26), cancelled turns stuck as 'working' (PATCH-37), several limits made explicit.

### Kept but switched off on this setup (capability switches, author to enable where verified)
- Model / effort change from the tray (PATCH-31/32/34, config capModelChange): Desktop's effort sub-menu opens only on hover/keyboard and opening the menu activates Desktop -> several clicks, windows popping up.
- Parking Desktop off-screen when minimized (PATCH-33/34, capParkDesktop) and per-operation hiding (PATCH-29/30, capGhostDesktop): Windows activates the restored window, read as 'user brought it up' -> it kept coming back after minimizing with Desktop's own button.
- Rename of Desktop local chats is ON again after PATCH-28 (navigation); claude.ai rename uses the existing call. Grey-out rules in caps.

### Problems we hit (details in each patch)
- Wrong first diagnosis (PATCH-1, reverted). Desktop 'Allow' buttons ignore programmatic presses (deny works) - handed over to Desktop, not worked around (PATCH-21/22). Desktop minimized = UI tree frozen (PATCH-10). Two parse errors from our own edits, caught by the parse step before any restart (PATCH-26). A sandbox reset lost the copy of the originals; rebuilt by reverse-applying the diff (sizes matched).

### Known limits / untested
- Undocumented Desktop internals: local_*.json fields, transcript format, UI class names, sidebar entry names ('<status> <title>'), localized words for a few fallbacks (send / skip / feedback, FR/EN + some). May break on Desktop updates.
- Waits on the UI thread (~1 s typical, a few s worst case) when acting in Desktop. Multi-choice / multi-question cards: answered in Desktop.
- Untested: classic Desktop installer, custom --user-data-dir, multi-org / multi-account, PowerShell 7, other UI languages, multi-monitor with pinned panel.
- User preferences rather than fixes (author may want settings): 'BROWSE' header, 'Hidden from the tray' block removed, bottom-anchored panel, 10-min cooldown default.
- Other feedback: bridge-mode [tray] line has no step output; failed ps steps show only the error tail; SKILL.md now names the target fields (cmd / path / url); quest helper names can collide with PS aliases; the personal skill zip kept `<QUEST_ROOT>` unfilled when -QuestRoot was never run.
